## 工程运行说明

版本：v0.2，2026-10-09。本目录提供本机环境检查、首轮证据核对及96条整批工程验证记录的统一入口，另有13项离线检查。首轮完整用例仍在 Excel 中，原始执行记录仍在 `../qa-api` 中。全套679条历史记录的迁移尚未完成，产品未修复。

## 环境前提

已验证的环境是 Windows PowerShell、Python 3.14.7、httpx 0.28.1、pytest 9.1.1 和运行中的 Docker。后端固定提交 `13db1fcef36bee9ce45d2d636a1d4e8f5ed5bbc3`，前端固定提交 `838965c5a18d2c61b73ec30c6e288057aaa08b63`。不同版本须重新核对业务预期。

当前原实例是 18080/18081，隔离副本是 18082/18083。数据库必须是 `qa_all_` 开头，后端容器必须是 `qa-all-backend-` 开头，MySQL 容器业务账号须能读取该库。此工程专用于这一隔离方案，不声称可以直接连接任意若依部署。它不会创建数据库、安装 Docker 或自动启动环境。

默认优先查找本目录 `.venv`，其次查找学习目录已有 `.venv`。新电脑需先准备官方源码和隔离环境，再在本目录准备独立 Python 环境。以下命令只复制代码块内部，不复制开头结尾的反引号。

```powershell
# 在工程目录创建环境；py 不可用时换成已安装 Python 的绝对路径。
py -m venv .venv
& '.\.venv\Scripts\python.exe' -m pip install -r requirements.txt
```

## 配置

将 `config.example.json` 复制为 `config.local.json`，填写当前隔离数据库和后端容器名称。部门、角色必须是事先准备好的有效测试数据。当前本机配置已从现存隔离副本清单生成，并通过实际 JDBC 与数据库核对；换副本后需要更新它。

配置里不保存管理员密码、数据库口令或访问令牌。数据库口令仅由容器内的业务账号环境变量传给 MySQL 客户端，不输出到控制台。

## 五种运行模式

```powershell
# 配置保护检查：默认模式，不访问若依或数据库。
& '.\运行测试.ps1' -Mode Validate

# 首轮证据核对：只读历史文件，不重新执行业务测试。
& '.\运行测试.ps1' -Mode Evidence

# 实时只读检查：匿名访问应被拒绝，并检查业务表准备状态。
& '.\运行测试.ps1' -Mode ReadOnly

# 执行只读检查及3项临时用户测试；会提示输入管理员令牌。
& '.\运行测试.ps1' -Mode Users

# 一次执行完整96条工程检查；独立准备及清理本条样本。
& '.\运行测试.ps1' -Mode Batch
```

可以用 `-PythonPath` 指定解释器，`-ConfigPath` 指定配置，`-EvidenceRoot` 指定原 `qa-api` 目录。退出码非零会提示本轮未全部通过，记录保存在 `runs/时间_模式/`，包含日志、JUnit XML及执行摘要JSON。ReadOnly模式选中24项，不调用管理员fixture或写入接口。Users模式维持原来的7项小入口，日常整批使用Batch。

Users或Batch模式前，先在 `http://127.0.0.1:18083` 手工完成验证码并以 admin 登录。浏览器开发者工具“网络”中选择一个登录后的业务请求，从请求头复制 `Authorization` 值，粘贴到入口的隐藏输入处；带 `Bearer` 前缀也可以。不要将令牌贴进聊天或写进文件。工程不读取 Redis 验证码，也不自动完成验证码。

未提供有效管理员令牌，写入测试会报准备失败，不会伪装成通过。用例运行时不得有其他用户操作、定时任务或并发脚本修改用户及关联表，否则全表不变量无法用于归属判断。

## 写入测试验证什么

| 测试 | 核对点 | 清理 |
| --- | --- | --- |
| 正常新增用户 | 业务成功、用户字段、角色关联、列表回读编号一致 | 按本条随机用户名找到的编号调用删除接口 |
| 重复用户名 | 拒绝重复请求，用户字段、密码指纹与关联快照不变 | 同上 |
| 31字符昵称 | 拒绝超长昵称，用户及关联快照不变 | 同上，包含异常落库时的清理 |

每条使用独立 `qe_` 用户名。`finally` 清理本条有效用户和关联，再比较原数据快照。若依删除是逻辑删除，测试会留下本条 `del_flag='2'` 历史用户及操作日志，不能说“数据库完全恢复到运行前”。不清理原始用户、原始角色或历史业务证据。

这3项来自已审核过的用户管理场景。另有49条常规模块验证：部门、菜单、岗位、字典类型、字典数据、参数设置、公告各7条，覆盖新增、详情、精确筛选、修改、空名称、名称超限及缺少必填字段。每条单独准备对象；字典数据还单独准备父字典。对象通过业务接口创建及删除，数据库入口只读。

部门表没有备注字段，使用本条专属的 `qe_...@example.invalid` 邮箱定位；其他模块使用本条备注定位。清理不会按全库新增编号差集删除其他来源的数据。删除后核对原业务表快照；部门的逻辑删除历史行及审计日志会保留。

读取入口覆盖20个受保护地址，分别检查匿名拒绝及管理员可访问，共40条；再加原小入口的4项读取/准备检查。96是执行记录数，包含原小入口与整批入口重合的匿名场景，不宣称96个互不重叠的独立业务场景。迁移目录关联48条首轮常规场景；公告缺省标题等输入变体按工程记录保留，不修改首轮总数。

本轮是未修改产品条件下的工程验证重跑，修复回归尚未开始。对会话变化、跨身份数据范围、并发、性能、安全载荷、页面等历史用例，原证据保留，尚未全部迁入新工程。

## 历史脚本为什么没有直接整批重跑

`qa-api` 中的完整执行脚本包含历史清单路径、导入时 Docker 操作、临时数据准备、缓存清空和性能安全探测。部分旧脚本通过 Redis 读取本地验证码，只属于当时隔离实验的实现，不能移植为真实环境的登录测试流程。直接运行可能改变副本或失去会话。

本入口不导入这些脚本，不自动重跑清空缓存、并发写入、压力、安全载荷等用例。以后逐步迁移完整套件时，需要按模块拆 fixture、准备策略、验收规则和执行开关；页面验证码继续手工完成。

## 持续集成的使用范围

`quality.yml` 在云端Windows运行器执行语法、脱敏目录及13项离线检查，保存JUnit。它不需要业务口令，也不连接用户电脑上的本机服务。

`local-api.yml` 仅人工触发，需要专用自托管Windows运行器及 `ruoyi-qa` 标签。运行器进程须提供：`RUOYI_CONFIG_PATH`（checkout目录外的本机配置）、`RUOYI_PYTHON_PATH`（已准备依赖的解释器）。选择Batch时，还须在手工登录后把有效 `RUOYI_TEST_TOKEN` 注入该运行器进程；不把令牌写进仓库或工作流。默认只读模式，不允许PR自动访问本机隔离库；并发组禁止同时运行两轮接口测试。

两份工作流采用JSON兼容的YAML格式，由Python标准库严格解析；Actions固定到已核对的公开提交。使用依据见官方 [checkout](https://github.com/actions/checkout)、[setup-python](https://github.com/actions/setup-python)、[upload-artifact](https://github.com/actions/upload-artifact)。Python依赖版本已核对 [httpx 0.28.1](https://pypi.org/project/httpx/0.28.1/) 与 [pytest 9.1.1](https://pypi.org/project/pytest/9.1.1/)。

本轮实际执行与迁移边界见交付目录中的 `若依测试工程批量迁移与CI验证记录.md`。自托管运行器尚未注册；上传配置并不代表已经连接本机环境。
